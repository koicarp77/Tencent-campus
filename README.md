# 审图台 · Review Desk

一个可本地运行的图片批注工具：点击问题位置、输入说明、显式保存，再次打开恢复。Vue 3 + TypeScript / Node.js + TypeScript / 本地 SQLite（包括图片二进制）。

项目每个源码、配置、脚本和测试文件的用途，以及“可复现的错误”的解释，见 [项目文件说明](docs/项目文件说明.md)。

## 一键启动（macOS）

安装 Node.js 24 LTS 后，直接双击项目根目录的 **`start.command`**，或在终端运行：

```bash
bash start.command
```

脚本会检查环境与端口、安装缺失依赖、幂等初始化数据库、构建并启动整个项目。首次安装需要联网；后续依赖齐全时会跳过安装。已有图片和标注会保留。

启动成功后打开 **http://127.0.0.1:3001**。请保持终端窗口开启，按 **Control+C** 停止服务。若端口占用，先关闭旧服务，或执行 `PORT=3002 bash start.command`，再打开对应端口。macOS 若提示无法直接打开，可使用上面的终端命令。

## 环境与启动

推荐 Node.js 24 LTS（`.nvmrc`），npm 10+。本次实际环境为 macOS / Node 26.5.1 / npm 11.17.0。

```bash
npm ci
npm run db:setup
npm run dev
```

打开 http://127.0.0.1:5173。开发 API 为 http://127.0.0.1:3001，Vite 将 `/api` 代理到它。开发模式请保持 API 端口为默认值。

生产运行（同一个端口提供页面和 API）：

```bash
npm run db:setup
npm run build
npm start
```

打开 http://127.0.0.1:3001。`PORT` 可修改生产端口，`DB_FILE` 可指定绝对数据库路径；默认 `data/review.sqlite`，不依赖启动工作目录。服务只监听本机。账号无需密码，按名字区分身份；同一群组成员共享图片与标记。已有批注不会被重复执行的 `db:setup` 清空。

## 登录、注册与群组

首次打开是登录界面。可以注册一个新账号，也可用已有演示账号「小林」或「小周」直接登录。账号名为1—32个字符，首尾空格会去除，统一全半角并转小写判断重名；重名注册会提示直接登录。按要求没有密码，知道账号名即可登录该身份，不作为真实身份认证。

登录后进入群组大厅：

1. 填写唯一群组名，点击「创建并进入」；群组名1—50个字符，采用与账号相同的规范化规则。
2. 也可以按群组名字搜索，点击「加入并进入」，无需创建人审批。再次进入已加入群组直接点「进入群组」。搜索是字面子串匹配，最多返回100组，可以输入更具体的名字缩小范围。
3. 组员权限一致：都可以上传图片、查看和新增/修改/删除标记。非组员不能访问该组图片内容或批注，即使知道图片ID。
4. 群组之间的图片列表隔离；审图界面顶部显示当前群组与登录账号，可以切换群组或退出登录。有草稿时离开会要求明确确认。

原有图片、批注和作者在启动时迁移到「默认协作组」，不会清空。演示账号已是该组成员；新注册账号可以搜索并加入。新建群组初始为空，上传图片即可开始。登录会话保存在本地SQLite中，浏览器通过HttpOnly Cookie保持30天，退出登录立即撤销当前会话。

## 图片标注

1. 进入群组后选择图片，或上传 PNG、JPEG、静态 WebP。默认协作组内置海报和长商详图。
2. 点击图片落点，右侧填写说明。Enter保存，Shift＋Enter换行；中文输入法选词确认不会误触保存。
3. 普通滚轮及Mac双指上下/左右滑动移动图片；Shift＋滚轮或双指捏合缩放，范围10%—400%。也可使用适应宽度、50%、100%、200%，100%为原始像素尺寸。
4. 每图最多100个标记，每条说明去首尾空白后1—500个Unicode字符。点击圆点或列表选中后按Delete/⌫删除，输入文字时仅删除文字。删除仍需保存。
5. 保存先提交有效修改，未完成项继续保留当前草稿并显示「部分已保存」。已有标记说明暂不合格时保留其上次保存内容，补全后再保存。自动备份会保留最近确认写入的草稿；明确放弃会清理备份，尚未成功备份的输入仍可能丢失。
6. 切换图片有草稿时可保存、放弃或取消；离开群组/退出登录有草稿时会先确认并等待备份成功，再离开。保存时后端基于服务端旧版本快照合并修改；同一标记被双方改成不同内容时另存为两个独立标记。网络中断先核对服务端，不自动覆盖他人修改。

图片原始大小和处理后大小均限制10MiB，解码限制2000万像素。按真实格式校验、拒绝动画、统一EXIF方向并移除元数据。账号、会话、群组、成员、图片BLOB及批注全部保存在同一个本地SQLite文件中。

## 崩溃与刷新后的草稿恢复

新增、删除标记或输入说明后，停止输入约0.5秒自动备份；持续输入时最多约2秒触发一次备份，实际写入仍受服务连接速度影响。页面会显示「草稿待备份／正在备份／草稿已备份」；失败时显示原因并提供重试，不能把待备份当成已成功。

备份按账号、图片和编辑窗口分开，保存在同一个本地SQLite的review_drafts表中，不使用localStorage或IndexedDB保存业务草稿。它不会修改正式图片revision，也不会让其他账号看到尚未提交的文字。

浏览器或页面异常退出后：重新启动服务（如果服务也退出了），用同一账号进入同一群组，打开原图。检测到备份时，可选「恢复草稿」或明确「放弃备份」；多个窗口的草稿可以分别选择。空说明、换行、未完成文字和删除标记的操作都能备份。恢复后仍需点击保存/按Enter，才成为群组内正式标注。

如果正式标注版本已变化（例如其他人已保存），恢复后仍可保存，后端比较旧基准、当前内容和本次修改，保留双方不同内容。旧基准不可用或合并超过100条时才拒绝并保留草稿。正常保存成功会清理当前编辑分支；部分保存后仍未完成的内容继续备份。切图时明确放弃会清理对应备份；离开群组/退出登录会先等待备份成功。

边界：只能恢复最近成功写入的内容。浏览器突然崩溃、断电或服务断开前的最后瞬间输入可能来不及备份；本机SQLite文件损坏或丢失也不属于此功能的恢复范围。单个草稿标记可暂存最多5000个Unicode字符（正式说明仍为1—500），草稿请求上限2MiB；超过限制会明确显示备份失败，不会静默截断。

## 删除照片与群组

- **删除照片**：在审图页选择照片，点击顶部「删除照片」。只有该照片上传者或群组创建者会看到入口，也只有他们能调用删除接口。
- **删除群组**：先点击「切换群组」回到大厅，在自己创建的群组卡片中点击「删除群组」。仅群组创建者可删除。
- 两种删除都会弹出明确确认，操作为永久删除：照片连同其所有标记和草稿备份删除；群组连同组内全部照片、标记、草稿及成员关系删除，但成员账号和其他群组保持不变。照片存在未保存草稿时会额外提示。
- 照片删除带当前revision，若其他组员已修改标记会返回冲突，需加载最新版本再确认。删除失败保留页面和草稿；网络中断会先查询资源是否已消失再确认结果。
- 「默认协作组」是系统预置组，没有个人创建者，不允许删除。演示图片由「小林」上传，可由该账号删除；删除后重新初始化或启动不会将图片复活。普通群组的最后一张照片删完后仍可继续上传新图片。

## 接口约定

- 账号：`GET /api/auth/session`、`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/logout`。登录/注册JSON为`{"name":"账号名"}`。
- 群组：`GET /api/groups?search=关键词`、`POST /api/groups`（JSON `{"name":"群组名"}`）、`GET /api/groups/:id`、`POST /api/groups/:id/join`。
- 图片列表及上传：`GET /api/images?groupId=群组ID`、`POST /api/images?groupId=群组ID`，上传文件字段仍为`image`，标题字段为`title`。
- 图片内容与review路径保持原样；正式保存使用 `PATCH /api/images/:id/annotations` 增量接口（详见下节），旧PUT整批接口保留兼容。后端按图片所属群组校验会话成员身份。上传者和批注操作人从会话取得，客户端`actorId`不能改变身份。
- 删除：`DELETE /api/groups/:id`、`DELETE /api/images/:id`（JSON `{"baseRevision":当前版本}`），后端校验创建者/上传者身份，照片删除还校验版本号。
- 私人草稿：`GET /api/images/:id/drafts`列出本账号备份，`GET/PUT/DELETE /api/images/:id/drafts/:draftId`读取/备份/清理。写入和清理使用独立草稿版本，仍要求有效会话及组员身份。
- `GET /api/health`无需登录，其余群组、图片与成员接口需要有效会话。

本版本仍为本机服务，群组数据在同一服务内共享；从其他电脑协作需要共同访问同一个部署，多个各自运行的SQLite副本不会自动同步。

## 常见问题

- 缺少初始化提示：先执行 `npm run db:setup`，确保启动与初始化使用相同 `DB_FILE`。
- 端口占用：关闭旧进程；e2e 不复用已有服务。生产可设置 `PORT`。
- 安装原生依赖失败：使用 Node 24 LTS；better-sqlite3 若无预编译包，需要系统 C++ 构建环境（macOS Command Line Tools）。
- Chromium 缺失：先执行 `npx playwright install chromium`。
- 页面显示无法连接服务：开发模式检查 API 3001 进程；生产先构建再 `npm start`。
- 查看上方草稿备份状态：刷新/关闭后可恢复最近成功备份的内容，但最后未备份输入仍可能丢失。正式提交仍需保存标注。数据库备份应在服务关闭后复制 SQLite 文件，或使用 SQLite 备份工具。

完整干净克隆验证：提交当前改动后运行 `node scripts/verify-clean.mjs`。脚本创建无依赖、无数据库的临时克隆并运行安装和完整验证，默认要求本机 Chrome，可用 `E2E_BROWSER_CHANNEL=chromium` 选择已安装的 Playwright Chromium。原始日志见 [clean-run.log](docs/verification/clean-run.log)。

## 并发保存规则

后端使用 `review_versions` 中的正式版本快照做三方比较，处理时间由服务端生成，客户端时间不参与排序。新增标记按创建时间排序；同一标记的不同并发修改：第一份保留原ID与创建历史，后一份生成新ID、记录本次提交者和时间并排在后面。同位置编号并排显示，实际坐标不变。

旧页未改动的标记不覆盖新内容；旧页看不到的他人新增不会被误删。删除与修改同时发生时优先保留修改；修改已删除的标记会另存新ID。相同内容和坐标的重复修改不复制。合并后最多100个标记，超限整笔不写入。迁移前不存在的旧基准也不会猜测合并，而是提示保留草稿并加载最新版本。

前端为每次提交生成 `submissionId`，相同内容重试复用它；后端通过 `review_submissions` 返回原结果，避免响应丢失后产生重复标记。`GET /api/images/:id/submissions/:submissionId` 仅向提交者提供成功收据。版本快照与收据随图片删除级联清理，保存越多会占用更多SQLite空间。现在通过SSE通知同组页面自动读取最新结果，无需刷新；正在编辑时保留草稿并展示最新共享变动。


## 增量保存标记

点击保存或按Enter时，前端只发送新增、修改、删除的标记，不发送未改动的标记。`PATCH /api/images/:id/annotations` 请求示例：

```json
{
  "submissionId": "本次提交的UUID，重试复用",
  "baseRevision": 3,
  "added": [],
  "updated": [{"id": "已修改标记的UUID", "x": 0.25, "y": 0.3, "content": "价格应为259元"}],
  "deleted": []
}
```

`added`只放新标记，字段与`updated`相同；`deleted`只放被删除标记的UUID。说明暂不合格的已有标记不会提交修改或删除，新的未完成标记留在草稿。后端从SQLite正式版本快照取可信基准，应用明确操作后进行三方合并，继续保留同一标记的不同并发修改、删除冲突中的修改、同位置独立新增；操作列表遗漏某标记不表示删除。每张图最终仍最多100条。

数据库只新增、更新或删除实际受影响的标记记录；删除后的编号可能需要重排。正式版本快照和成功收据仍在事务中保存，以支持旧版本合并、响应丢失核对及重试去重。原 `PUT /api/images/:id/annotations` 整批接口为兼容旧脚本而保留，当前页面正式保存均使用PATCH。

这里减少的是正式保存时的上传数据：后端保存响应仍返回完整合并结果，前端据此显示双方内容；私人草稿备份仍传完整快照，以恢复空说明、未完成文字和删除操作。实时同步机制见下节。


## 实时同步

同群组成员保存标记后，其他已打开的审图页面会自动更新，无需刷新。图片上传、删除也会自动更新同组图片列表。顶部显示「实时同步已连接」；断线会提示重连，重新连接及页面回到前台时补查最新数据。私人未保存草稿不会推送给其他账号。

如果你正在编辑，最新共享变动会出现在单独面板中：你的输入、选中项和原编辑基准保持不变，不会把其他人的文字混入本地草稿。点击保存后，后端仍使用原基准进行增量合并，同一标记的不同修改分别保留。正在保存、核对结果或切换图片时收到的通知会等待操作结束后补查。

如果照片或群组被其他人删除：无草稿时切到剩余图片或显示空态；有草稿时保留页面内容供复制，提示资源已删除并禁止继续保存。登录身份/权限失效后停止实时连接和编辑，避免旧窗口在新身份下继续操作。

实现为 `GET /api/groups/:id/events?owner=当前账号ID` 的SSE长连接，只发送变更类别、图片ID和版本号，页面通过有权限检查的普通接口读取最新数据。连接时、发送前及心跳时检查会话和群组成员；退出登录/换号关闭失效连接。连接断开、组件离开后清理监听和重试任务。通知在当前Node进程内分发，适用于目前的单服务部署；不提供多实例消息总线或持久事件回放，重连以当前SQLite状态补齐。

验证实时机制：`E2E_BROWSER_CHANNEL=chrome npm run test:e2e -- tests/e2e/realtime.spec.ts`。编辑保护的真实页面见 [实时更新与本地草稿](docs/verification/realtime-editing.png)。
