## 本次结果

测试采用10、50、100个闭环HTTP worker，以及10、50、100条SSE连接。共有100个模拟账号，未启动真实浏览器。测量HTTP请求72,871次，72,870次成功；唯一非2xx为第101份标记触发的预期409业务保护，无非预期错误。181项一致性检查通过。

以下均为100并发参数下的数据；p95表示95%的已完成样本耗时不超过该值：

| 场景 | 样本/负载 | p95 |
| --- | --- | --- |
| 普通读取 | 20,000次；每图10条、每条100字 | 10.0 ms |
| 满载标注读取 | 6,280次；每图100条、每条500字 | 88.4 ms |
| 独立图片增量保存 | 100个worker各20次；每图10条 | 71.3 ms |
| 同一标记并发修改 | 100账号同一基准提交100份不同内容 | 131.7 ms |
| SSE通知收到 | 100连接×10次保存，1,000/1,000条收到 | 11.0 ms |
| SSE通知后补查完成 | 含50ms合并及图片列表、review读取，不含绘制 | 128.3 ms |

同标记并发场景最终保留100条独立标记、100位不同修改人；第101份被原子拒绝，未改变数据。SSE全部连接追上最终版本，无异常断流。服务采样峰值RSS约230.45MiB。最终测试库约55MiB，压缩归档约2.47MiB，包含正式版本与提交收据。

这是本机回环、客户端与服务端同机的**短时测试**。普通读取三个阶段均达到20,000请求封顶，实际各约2秒，并未连续跑满配置的10秒。SSE仅按每250ms保存一次、共10次测试。不能据此宣称最大承载用户数、长时间稳定性或公网性能。

## 重新运行

在项目根目录执行：

```bash
npm run test:load
```

脚本自动构建生产入口，创建合成账号/图片、临时数据库和本机随机端口，运行10/50/100并发场景，保存带时间戳的结果目录，然后关闭自己的服务、归档并清理临时库。不会使用已有3001端口，也不接受外部目标地址。HTML和Markdown报告生成需要Python3；即使缺少Python3，JSON/CSV原始结果仍保留。

参数示例（小规模校验）：

```bash
npm run test:load -- --levels=2,5 --read-seconds=1 --write-iterations=2 --sse-updates=2
```

只重新生成报告：

```bash
python3 scripts/render-load-report.py docs/verification/load-test/2026-11-01T06-08-30-117Z-c69915/summary.json
```

每轮会生成新目录，不覆盖旧数据；latest.json会指向最新一轮。
